# 绿色债券发行链路模拟

安装依赖后，运行 `python run.py`，按终端提示打开 Streamlit 页面。

```bash
pip install -r requirements.txt
python run.py
```

建议使用 Python 3.10+ 和独立虚拟环境。更新本项目后重新安装依赖，以启用静态图表和文本分析。

## 图表与决策理由分析

在「统计与文本分析」选择历史场景，可查看交互式漏斗、各环节失败率和企业性质留存。文本分析默认使用首次失败理由，可以切换为全部已到达环节，并按判断来源、环节、停用词筛选。同批次 P0–P6 可以合并分析。

- pandas 读取和整理企业表格。
- Plotly 绘制页面交互图。
- matplotlib 和 seaborn 生成阶段留存图、失败率热力图、单场景企业性质留存图和理由高频词图。勾选「生成并预览静态报告」后可下载 PNG 或完整 ZIP。
- jieba 进行中文分词，使用绿色金融领域词典和停用词，输出出现次数、包含该词的理由数及理由覆盖率。可展开原文并导出 CSV／JSON。

词频按理由条数统计，重复实验按记录计数。默认首次失败范围中，每条失败记录计一条理由。全部环节范围中，同一企业不同环节分别计数。模型、规则、硬规则、降级和来源未记录的历史文本可分别筛选。词频用于描述文本，需要结合原文和场景对照解释。

报告 ZIP 包含 PNG、环节统计 CSV、词频 CSV、原文及文本统计 JSON、场景汇总和筛选参数。命令行可直接分析已导出的 JSON，无需重新调用模型。

```bash
python run.py --analyze results.json --output report.zip
python run.py --analyze results.json --output llm_report.zip --source llm --scope all --top-n 20
```

Windows 优先使用微软雅黑。Linux 推荐安装 Noto Sans CJK，Dockerfile 已包含该字体。接口、字段、来源标记与导出格式见 [接口文档](docs/接口文档.md)。运行 `python -m unittest discover -s tests -v` 可检查分词计数、来源筛选、历史数据、报告导出和页面操作。

## 导入第一组的发行决策

CSV 是用逗号分隔列的文本表格。Excel 可以打开 CSV，也可以通过「另存为」导出 **CSV UTF-8**。系统也接受 Excel 的 `.xlsx` 文件。请在 Excel 中将企业编号列设为文本，以保留 `000001` 等编号的前导零。

在左侧选择「上传第一组企业名单」。如果文件包含全部企业，请用 `decision` 或「发行决策」标明每家企业的最终决策（`1`／「发行」或 `0`／「不发行」）。系统只载入愿意发行的企业。如果第一组已筛好名单，且文件没有决策列，勾选「已确认名单仅含愿意发行的企业」。每家入选企业应有一个唯一的原始编号。

| 字段 | 中文列名 | 示例 |
| --- | --- | --- |
| `firm_id` 或 `code` | 企业编号 | `000001` |
| `credit_rating` | 信用评级 | `AA`（支持 AAA、AA+、AA、A、BBB、BB） |
| `asset_liability_ratio` | 资产负债率 | `0.65` 表示 65% |
| `green_level` | 绿色程度 | `high`、`medium`、`low`，也可填高、中、低 |
| `has_green_project_cert` | 绿色项目证明 | 是／否 |
| `has_financial_report` | 财务报告 | 是／否 |
| `has_financing_plan` | 融资方案 | 是／否 |
| `decision` | 发行决策 | 发行／不发行。已筛选名单可省略此列。 |

还可提供企业名称（`firm_name` 或 `name`）、所有制、行业、合规评分、发行规模等字段。第一组的最终决策用于决定企业是否入池，发行意愿得分可作为附加字段。正式实验前，两组应核实缺失字段和模拟默认值。

以下是两条虚构记录，可作为 CSV 格式示例。

```csv
firm_id,firm_name,decision,credit_rating,asset_liability_ratio,green_level,has_green_project_cert,has_financial_report,has_financing_plan
000001,示例企业甲,发行,AA,0.65,medium,是,是,是
000002,示例企业乙,不发行,A,0.72,low,是,是,否
```

上传后先核对预览中的企业，再选择场景并点击「开始批量实验」。每个场景按名单逐家运行一次，并保留原始企业编号。「示例数据」模式可以按设定轮数重复抽样。

## 对照 P0–P6

在「批量实验」选择「P0–P6 场景对照」，再点击「运行 P0–P6」。七个场景共用同一批企业和原始企业编号。每个场景逐家运行一次，页面展示成功率及其相对 P0 的变化。SQLite 使用同一批次编号加场景代码保存明细。

| 场景 | 相对 P0 的变化 |
| --- | --- |
| P0 | 中等认证、中等监管、稳健承销、均衡投资 |
| P1 | 放宽认证 |
| P2 | 收紧认证 |
| P3 | 放宽监管 |
| P4 | 增强投资者 ESG 偏好 |
| P5 | 提高承销商风险偏好 |
| P6 | 放宽认证与监管，同时增强投资者 ESG 偏好 |

规则模式及 LLM 降级后的规则判断，使用同一企业、同一环节的配对随机数。LLM 本身的回答仍可能变化。示例模式使用同一批 20 家合成企业做演示，正式实验需要上传实际企业名单。选择「单个自定义场景」可以继续使用侧栏里的场景配置。

## 审核、定价和结果

可选输入 `project_catalog_eligible`（符合项目目录）与 `major_violation`（重大违规）可填写是、否或留空。请按适用市场、发行日期与发行品种核对公开材料。认证与监管记录有通过、有条件通过和拒绝三种结果。有条件通过携带补件意见继续模拟，结果代表补件条件下的情景。程序中的负债率 80% 和连续两年盈利检查是原有模拟假设，适用性需要用项目材料另行核验。

如需用市场数据定价，请同时填写 `market_benchmark_yield`（小数，例如 `0.013`）与 `pricing_spread_bp`（基点，例如 `34`）。利差应来自有出处的校准样本。可用 `issuer_rate_cap`（小数）提供发行人票息上限。市场基准加利差后仍会应用承销风格调整，超过发行人上限时记录为不承销。没有市场输入时，程序使用原有模拟定价。公开定价小样本用于比较预测误差。

「统计与文本分析」可按历史场景查看漏斗、占全样本失败率、到达该环节后的失败率及企业性质留存曲线，并导出同批次逐企业明细。新记录携带规则版本、规则种子和 LLM 模型参数，实际调用失败产生的规则结果单独标记。

也可以通过命令行用固定种子复跑。文件已筛选且没有决策列时，加上 `--prefiltered`。输出路径应指向一个新文件。

```bash
python run.py --preset firms_willing.csv --seed 42 --output results.json
```
