# 链路组 2 绿色债券发行模拟流程

第一组判断哪些企业具备基本条件并决定发行。链路组 2 接收愿意发行的企业，逐家模拟企业发起、绿色认证、监管审核、承销定价、投资认购，回答**企业卡在哪一关、为什么被卡住、调整哪一环节能改变模拟结果**。五关是研究模型采用的顺序。对真实流程的描述应明确市场、券种和发行日期，当前校准范围是银行间非金融企业绿色中票。

对照《项目说明-ST》第 5–7 页、《LLM 模拟研究方案 v2》第四至六部分、《LLM 技术实施方案 v2》第一和第四部分，以及《LLM2 四月进度汇报》。 [项目共享目录](https://box.nju.edu.cn/d/073e47ef997e47cb8378/) · [研究方案](https://box.nju.edu.cn/d/073e47ef997e47cb8378/files/?p=%2FLLM%E6%A8%A1%E6%8B%9F%E7%A0%94%E7%A9%B6%E6%96%B9%E6%A1%88_v2.md) · [技术实施方案](https://box.nju.edu.cn/d/073e47ef997e47cb8378/files/?p=%2FLLM%E6%8A%80%E6%9C%AF%E5%AE%9E%E6%96%BD%E6%96%B9%E6%A1%88_v2.md)

## 一 从资料准备到研究成果

| 步骤 | 链路组 2 做什么 | 产出和当前进度 |
| --- | --- | --- |
| 1. 确定模拟范围 | 梳理真实案例里各主体的职责、材料及停止条件，区分案例事实和实验假设 | 五关模型已实现。已有公开绿色中票样本和定价检验。逐券种规则、补件和反馈证据待补 |
| 2. 接收第一组名单 | 从 CSV/XLSX 读取企业资料；无表格时从 Word／文字提取字段，标记待核实项并导出 CSV/XLSX。按最终发行决策筛选，核对编号唯一性。已筛名单可显式确认无需决策列 | 导入、文字提取、缺失提醒与预览已实现。正式名单、决策场景、数据日期与缺失字段口径待组间确认 |
| 3. 设计五类主体并做原型 | 给每类主体规定角色、看到的信息、判断方式和输出。先用 Coze 或 Dify 跑少量样例，检查每关有没有读到上游字段 | 四月汇报记录了学习与环境尝试。本文补了原型节点图和验证用例。可回放的工作流、截图和调试记录仍待提供 |
| 4. 迁移到 Python | 把企业整理成结构化上下文，用 Python 顺序调用各角色，记录每步结果与首个终止点。规则模式可独立运行 | Streamlit 界面、命令行、顺序编排和 LLM 接口已实现。真实 API 的成功及降级记录待随正式实验归档 |
| 5. 做 P0–P6 配对实验 | 锁定同一批企业，每个场景逐家走一遍。P0 作为基准，P1 放宽认证，P2 收紧认证，P3 放宽监管，P4 提升 ESG 偏好，P5 提升承销风险偏好，P6 同时放宽认证、监管并提高 ESG 偏好 | 七个预设及配对规则种子已实现。研究方案目标为每场景 200+ 家企业，实际样本量以正式名单中的唯一企业数为准 |
| 6. 校准后复跑 | 用真实案例核对硬规则、票息、角色提示词和失败原因，登记改动，再用同一批数据复跑 | `research/evaluate_pricing.py` 可复算已有的小样本票息检验。审核、补件和认购环节的样本与校准待完善 |
| 7. 分析并与第一组合并 | 用漏斗看在哪一关流失，比较场景和企业性质，按企业编号把第一组意愿和第二组执行结果接起来 | 已可生成漏斗、两种失败率、失败归因、企业性质留存曲线和场景热力图。联合分析和论文结论等正式批次产出 |

企业交接的必需字段与填表示例见 [README](../README.md)。建议同时交接第一组的场景、名单版本及数据日期。联合分析可使用“名单版本或第一组场景 + 企业编号”，再在组 2 输出上附加“实验批次 + P 场景”，以免同一企业的多次结果被覆盖。

## 二 一家企业如何经过五关

| 环节 | 看什么、做什么 | 写出什么、何时停止 |
| --- | --- | --- |
| 1. 企业发起 | 企业已经入池。程序检查绿色项目证明、财务报告、融资方案三项是否齐备，两种模式都先做这一步 | 输出 `stage_1_material`。缺任一项记作企业发起失败，后续关口未到达 |
| 2. 绿色认证 | 先检查项目目录匹配标志和绿色证明真实性标志。通过程序检查后，再按认证风格和项目绿色程度判断 | 输出 `stage_2_certifier`，含审核结果、理由及补件条件。通过或有条件通过继续，拒绝即终止 |
| 3. 监管审核 | 先检查重大违规、负债率及连续盈利标志。再做合规判断。LLM 模式会把认证摘要作为监管输入 | 输出 `stage_3_regulator`，记录审核决定与意见。通过或有条件通过继续，拒绝即终止 |
| 4. 承销定价与路演 | 评估是否承销并形成票息和路演信息。LLM 模式读取两份审核摘要，规则模式可用市场基准加利差并做风格调整，缺少市场输入时采用内置定价假设 | 输出 `stage_4_underwriter`。承销拒绝或票息超过填写的发行人上限时止步 |
| 5. 投资认购 | 根据发行规模、票息、评级、绿色属性及投资偏好模拟认购。LLM 模式还能读到认证、监管和承销摘要。规则模式使用承销票息和路演质量进入概率计算 | 输出 `stage_5_investor`。认购金额达到发行规模记成功。部分认购或不认购均记失败 |

- **方案与实现的阈值差异。** 研究方案示例使用负债率超过 85% 的拦截条件。当前代码沿用超过 80% 和连续两年盈利的模拟假设。正式实验前应根据明确的市场、券种和时间口径复核并记录取值。
- **补件。** 两个审核环节都可记录“有条件通过”，企业携带相关意见继续模拟。真实补交、复审、退出行为仍需样本和模型支持。
- **审核意见怎样传递。** LLM 编排显式传递前序结构化意见。纯规则编排在认证和监管阶段用审核结果决定能否进入下一关，后续计算直接使用企业属性和承销结果。
- **认购细分。** LLM 模式明确输出足额、部分或不认购。规则模式保存认购金额、发行规模和是否足额，可按金额重算覆盖率。

实现入口：[engine.py](../engine.py) · [agents.py](../agents.py) · [rules.py](../rules.py) · [llm_client.py](../llm_client.py)

## 三 Python 实验与页面操作

1. 安装依赖，运行 `python run.py` 打开 Streamlit。试跑时用示例企业。正式运行时选择「上传第一组企业名单」，在「当前数据预览」核对入池规模、企业 ID 和关键列。
2. 先在「单次模拟」挑一家企业，看五关通过、失败和未到达状态。页面默认走规则模式。启用 LLM 后在侧栏输入自己的 API Key，再由 Python 检查硬规则，四个外部角色再按需调用模型，解析并校验 JSON。调用或结构校验失败时，该关以规则结果继续判定并标记 `fallback_rules`。
3. 在「批量实验」运行 P0–P6。每个场景用同一批企业，同一企业、同一环节使用配对的规则随机数。规则种子同样用于 LLM 降级结果。模型实际响应仍可能波动。上传名单后，自定义场景逐家运行。示例数据的自定义批量模式可以重复抽样。
4. 到「统计与文本分析」选择数据库中的历史场景。对照同一批次的成功率与 P0 的百分点变化，并下载逐企业 JSON。文本分析可用 jieba 按来源、环节筛选理由，核对原文与词频。勾选静态报告可用 matplotlib／seaborn 生成图表和完整 ZIP。命令行支持直接分析已有 JSON；运行命令见 [README](../README.md)，字段和导出格式见 [接口文档](../docs/接口文档.md)。

| 指标 | 计算方式与用途 |
| --- | --- |
| 整体成功率 | 成功家数 ÷ 进入该场景模拟的企业数 |
| 占全样本失败率 | 该关首次失败家数 ÷ 进入该场景模拟的企业数，用来比较各关的总体损失 |
| 到达后失败率 | 该关失败家数 ÷ 到达该关的家数，用来比较各关对实际到达企业的拦截强度。无人到达时留空 |
| 企业性质留存 | 本类通过该关家数 ÷ 本类进入模拟家数 |
| P0 配对变化 | 用原始企业编号匹配，分别统计由失败转为成功、由成功转为失败的家数 |

实现入口：[app.py](../app.py) · [scenarios.py](../scenarios.py) · [database.py](../database.py) · [run.py](../run.py)

## 四 Coze 或 Dify 原型节点

选任一平台建一条单企业工作流，输入 1 家虚构企业和 1 组场景参数。Dify 可用开始、代码、LLM、条件分支和结束节点表达同一流程。Coze 可对应为开始、代码、大模型、选择器与结束。以下是搭建时的节点连接和变量约定。

| 节点 | 输入或判断 | 写给后续节点的字段 |
| --- | --- | --- |
| 开始及发行人材料检查 | 企业编号、财务与绿色属性、三项申请材料、场景角色配置。代码节点检查材料 | 企业上下文和材料结果，缺件走失败出口 |
| 绿色认证 | 先做目录及真实性硬判断，再用认证角色提示词判断。输出进入条件分支 | `decision`、`reason`、`conditions`。拒绝走失败，条件通过保留条件 |
| 监管审核 | 读取企业上下文与认证结果。先做监管硬判断，再用监管角色提示词判断 | 同一组审核字段，供承销与投资节点读取 |
| 承销商 | 读企业、两份审核结果和可用市场输入。模型输出后由程序校验票息和发行人可接受上限 | `decision`、`issue_rate`、`rate_rationale`、`roadshow_strategy` |
| 投资机构 | 读认证、监管、承销结果和发行规模。解析认购响应并由程序比较金额 | `will_subscribe`、`subscribe_amount`、`decision_rationale`，金额单位统一为亿元 |
| 结束 | 成功或首个终止环节 | 企业编号、场景、终态、失败环节、失败理由、已到达环节结果 |

原型最少保留四种运行证据。用“材料齐备且足额认购”验证成功通路。用“目录不符”验证认证硬拦截和后续节点跳过。用“认证有条件通过”验证监管和投资节点实际读到补件意见。用“认购不足”验证终态和失败归因。调试时若模型输出无法解析，应显式记录技术错误，其后可重试并修正提示词。迁入正式 Python 流程时使用代码已有的规则降级分支。原型提交材料包括可编辑工作流或导出文件、节点截图、测试输入和实际输出。
