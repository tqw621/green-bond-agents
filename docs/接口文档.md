# 绿色债券链路模拟接口文档

本项目提供 Python 函数、命令行和 Streamlit 页面入口。五环节共用模拟引擎，静态报告和文本分析使用已有结果。下列示例从项目根目录运行。

## 企业输入与模拟入口

企业名单支持 CSV 和 XLSX，列名、必需字段和单位见 [README](../README.md)。企业编号作为字符串，负债率和收益率使用小数，定价利差使用基点，发行与认购金额使用亿元。

| 函数 | 输入 | 输出 |
| --- | --- | --- |
| `engine.validate_enterprise_dataframe(df, willing_only=True, prefiltered=False)` | pandas 表格。按发行决策筛选，有已筛名单时可设置 prefiltered | `(valid, message, processed_df)`，校验失败时按 message 修正输入 |
| `engine.load_enterprises_from_df(df)` | 校验后的表格 | 标准企业字典列表 |
| `engine.run_single_simulation(enterprise, ..., use_llm=False, rule_seed=None)` | 企业字典及认证、监管、承销、投资角色参数 | 单条模拟结果 |
| `scenarios.run_preset_experiment(enterprises, use_llm=False, seed=42)` | 唯一企业编号的企业列表 | P0–P6 到结果列表的映射，同一企业按环节配对规则随机数 |
| `engine.analyze_results(records)` | 非空结果列表 | 成功率、分环节失败率和失败分类。全部成功时瓶颈值为“无” |
| `database.SimulationDB.save_experiment(scenarios)` | 场景名称到结果列表的映射 | 在一个事务中保存批次，异常时回滚 |
| `database.SimulationDB.load_scenario(name)` | 历史场景名称 | 结果列表，兼容旧版环节详情 |

单条结果携带 `enterprise_code`、`enterprise_data`、`final_result`、`failure_stage`、`failure_reason`，以及五个环节字段。未到达的环节为空。已到达环节包含 `passed`、`reason`，外部角色另有 `detail`。五个环节的编号依次为 `1_enterprise_application`、`2_green_certification`、`3_regulatory_review`、`4_underwriter_pricing`、`5_investor_subscription`。

## 模型调用与结果校验

在本地 `.env` 配置 `LLM_API_KEY`、`LLM_BASE_URL` 和 `DEFAULT_MODEL_NAME`。默认模型为 deepseek-chat。页面选择「启用 LLM API 决策」后按需调用，温度由 `config.LLM_JSON_TEMPERATURE` 控制。硬规则先执行，四个角色通过 `LLMClient` 使用 OpenAI 兼容的 Chat Completions 接口。

| 角色 | JSON 响应字段 | 关键校验 |
| --- | --- | --- |
| 认证、监管 | `decision`、`reason`、`conditions` | decision 为 approved、conditional 或 rejected。条件通过须提供非空补件文本列表 |
| 承销 | `decision`、`issue_rate`、`rate_rationale`、可选 `roadshow_strategy` | decision 为 underwrite 或 declined。承销票息为 0–0.20 之间的小数，仍检查发行人上限 |
| 投资 | `will_subscribe`、`subscribe_amount`、`decision_rationale` | 决策为布尔值、金额为非负有限数，两者一致。金额达到发行规模才算成功 |

模型调用、JSON 解析或字段校验失败时，该环节执行规则降级，`detail.source` 为 `fallback_rules`。真正解析成功的模型结果为 `llm`，前置硬规则拦截为 `rigid_rule`。纯规则记录可由明确的 `use_llm=False` 识别。模型开关表示请求模式，实际来源以环节记录为准。

## 文本分析

```python
from analysis import analyze_decision_text

result = analyze_decision_text(
    records,
    scope="failures",
    source="all",
    stage="all",
    top_n=20,
    extra_stopwords=("当前",),
)
```

| 参数 | 取值与含义 |
| --- | --- |
| records | 模拟结果列表，支持空列表和只有最终失败理由的历史记录 |
| scope | failures 仅取首个失败环节理由，all 取所有已到达且有理由的环节 |
| source | all、llm、rules、rigid_rule、fallback_rules、unknown |
| stage | all 或上述五个环节编号 |
| top_n | 1–100 整数，默认 20 |
| extra_stopwords | 额外停用词序列，与内置停用词合并 |

分词使用 jieba 精确模式，关闭 HMM，加入绿色金融词典。仅统计长度大于 1 的中文或英文字词，英文转小写，去除数字、标点和停用词。排序依次按理由覆盖条数降序、出现次数降序、词语字典序。

输出 `terms` 包含 `term`、`count`、`document_count`、`document_rate`。覆盖率分母是筛选后的理由总条数。一条理由中多次提及同一词增加 count，document_count 只加一。同一失败记录的环节理由和最终失败理由合并计一次。多次模拟保持各自记录。

`documents` 保留企业编号、场景、环节、来源、原始理由及输入列表中的 record_index。`record_count` 为涉及的输入记录数，`document_count` 为理由条数，`source_counts` 为各来源理由数。缺少来源证据的旧记录归入 unknown。LLM 原始响应和技术错误字符串不进入分词。

## 静态报告与命令行

```python
from reporting import render_report

report = render_report({"P0": records}, scope="failures", source="all")
png_bytes = report["images"]["failure_heatmap.png"]
zip_bytes = report["archive"]
```

render_report 接受一个或多个非空场景，支持相同的文本筛选参数。输出 images 为 PNG 字节映射，archive 为 ZIP 字节，text_analysis 和 metadata 为结构化结果。所有统计图使用所选场景的全部模拟记录，文本筛选只作用于词频图和文本数据。

ZIP 固定包含阶段留存与失败率热力图、stage_statistics.csv、reason_terms.csv、text_analysis.json、scenario_summary.json、metadata.json。单场景另含企业性质留存图，有可用词语时另含 reason_terms.png。无人到达的关口在热力图留空。有中文字体时生成中文图表，缺少字体时界面和命令行提示安装。

```bash
python run.py --preset firms.csv --seed 42 --output results.json
python run.py --analyze results.json --output report.zip
python run.py --analyze results.json --output llm_report.zip --scope all --source llm --stage 2_green_certification --top-n 15 --stopwords 当前 建议
```

分析入口接受预设实验的 `{"summary": ..., "scenarios": ...}` JSON，也接受页面导出的结果数组。数组按 scenario_name 分组，缺失时归为 export。输出目录须存在，输出文件须为新的 .zip。错误输入由命令行返回非零退出码。
